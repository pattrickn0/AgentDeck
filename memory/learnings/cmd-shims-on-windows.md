---
title: .cmd shims on Windows: two passes in PTY and file-based prompts in headless
summary: In tabs, cmd_safe_arg escapes for cmd.exe /c and for the shim's %*; in headless, the .cmd is invoked directly and the prompt is passed via a file.
touches: [crates/core/src/agents.rs, crates/core/src/headless.rs]
---
A CLI installed via npm or pip on Windows is a `.cmd` shim. `cmd.exe` interprets `& | < > ^ % "` and line breaks,
and in an interactive tab (`portable-pty`) the text passes through **two** interpreter passes: the command line of
`cmd.exe /d /e:on /v:off /c <shim>` and the shim's internal line expanding `%*`.

**Why:** stripping special characters broke valid Windows paths (such as `C:\Users\Ana&Bia`), and passing an
unrestricted prompt on the command line would allow executing arbitrary commands via `cmd.exe`.

**How to apply:** in tabs (`spawn_spec_for`), every argument generated by the app passes through `cmd_safe_arg` (`agents.rs`),
which escapes for both passes (`^^^c` outside quotes, `%%cd:~,%` for `%`, with `/e:on /v:off`). Free-form text from another
agent never enters a shim's command line: the initial task prompt (`boot_prompt_flag`) is only a single ASCII line
pointing to a file, and in headless mode (`headless.rs`) the `.cmd` is invoked directly via `std::process::Command` (which
applies standard library batch escaping) with the prompt written to `data/prompts/` (`prompt_arg`).
